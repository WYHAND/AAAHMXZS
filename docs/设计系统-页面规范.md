### 2.1 已废止的写法（新代码零容忍）
- `bg-secondary text-secondary-foreground`（曾在改版后变成白字白底 → 每日一问答案看不见）
- `text-secondary-foreground` 配任何浅底
- 单靠 `bg-primary-soft` 表达选中（必须配 `ring-1 ring-primary/30` 或 `border-primary`）
- `bg-accent` / `bg-accent/50` 作为**大面积**面板底（浅桃只给小面积：chip、状态点、小按钮）
- 用 `text-xs` / `text-sm` 直接表达层级（要用语义字号阶）
- 14px 的数字用 `font-numeric`（等宽只留给 ≥24px 的展示数字与期间/日期列）

### 2.2 改颜色时的铁律（2026-10 踩坑记录）
**同一个颜色 token 只能在一处定义。** 这个文件里曾经有两份调色板（旧「浅米黄 + 克制蓝」
和新的 Serene Career Companion），两处都声明 `--secondary` / `--primary-soft` / `--border`。
后果：Tailwind 生成 `text-secondary` / `bg-secondary` 工具类时按**先出现的那份**解析，
于是首页的强调色（AI 小字、进度条填充）整片变成浅灰 —— 而且 `:root` 里后写的那份
**覆盖不了工具类**（工具类在 `@theme` 层解析）。现在只保留末尾一份，
并显式规定语义分工：

| 想要的效果 | 用什么 |
|---|---|
| 强调文字 / 强调数字 / 进度条填充 | `text-primary` / `bg-primary`（#091426） |
| 中性浅底（气泡、悬停、内嵌块） | `bg-surface-container` / `bg-surface-container-low` |
| 浅桃小面积强调底 | `bg-secondary-fixed` + `text-on-secondary-fixed` |
| 选中 / 悬停的浅墨底 | `bg-primary-soft` + `ring-1 ring-primary/30` |

新增颜色时：写进末尾的 `:root`，并在 `@theme` 里补一条 `--color-xxx` 映射；
**不要**在别处再写一份同名变量。

## 三、构件（唯一实现，页面里不要再手搓）

### `components/PageHeader.tsx`（页面标题区）
```
<PageHeader title breadcrumb? badge? description? actions? />
```
- h1 = `text-headline-xl`（**26px / 700 / 行高 34 / 字距 -0.015em**），颜色 `text-primary`
- 面包屑 = `text-caption`；描述 = `text-body-md`，最宽 `60ch`
- 右侧 `actions`：**最多一个实心按钮**（其余 outline / ghost）

### `components/Panel.tsx`（卡片）
```
<Panel padded? inset? as?>…</Panel>
```
- 默认：白底、12px 圆角、极轻阴影、**内边距 20px**
- `inset`：卡内浅底区块（`bg-surface-container-low`，8px 圆角，14px 内边距）——
  用它替代各处 `bg-muted/50`、`bg-card/80` 这类临时底色
- 页面一次只允许一种卡片外观；同一屏内边距不许出现第三种数值

### `components/StatGroup.tsx`（数字面板）
```
<StatGroup columns={2|3}><Stat value label unit? accent? divided? /></StatGroup>
```
- 数字 24px/700 `tabular-nums`（`size="display"` 时 32px，仅首页节律用），标签 12px caption
- `accent`（强调，主墨）**一屏最多一个数字**

### 首页图表（2026-10 新增）
- `components/ActivityStrip.tsx`：近 N 天每日活动柱，**手写**。只有「今天」用主色，其余用 `bg-primary/20`（单系列纪律）。
- `components/SignalBar.tsx`：证据强度信号条（呈现分布**形状**，不是打分，文案禁止「越满越好」）。
- `components/StatRing.tsx`：环形进度（done/total），底环 `surface-container-highest`、进度环 `primary`。
- `ProfileRadar` 新增 `compact`：只给雷达图，隐藏「真实数值」表与说明（首页用，默认 `false` 不影响个人中心）。
- 纪律：**这三个小图一律手写 SVG/CSS，不引图表库；整页最多一个 recharts（就是 `ProfileRadar`）**。是否该画用 `@/utils/profileEvidence` 的 `hasEvidence(tags)` 判断，避免留空容器。

### `components/PageShell.tsx`（页面外壳）
- 内容宽 **1040px**（与首页一致），纵向节奏 `gap-6`（24px）
- 标题区由 PageHeader 承担；页面内部要窄栏就自己收窄（如简历 `max-w-3xl`）

## 四、控件与文字

| 元素 | 规格 |
|---|---|
| 主按钮（全站唯一 CTA） | `variant="warm" size="lg"` —— **组件自带** 44px 高 / 12px 圆角 / 15px·600，页面里**不要再手写** `rounded-xl text-[15px]`（历史上每个页面各补一次，补漏了就出现"同屏两种圆角"） |
| 次按钮 | `size="sm"`（h-8 / 圆角 8 / 13–14px / 500）+ `variant="outline"` |
| 弱化动作 | `variant="ghost" size="sm"`，退到页面底部一行 |
| 区块标题 | `text-headline-sm`（16px/600） |
| 正文 / 字段值 | `text-body-md`（14px） |
| 次要说明 | `text-body-sm`（13px） |
| caption | `text-caption`（12px，仅装饰性小字；token 已从 #94a3b8 提亮到 **#6b7280**，白底 4.83:1 / 浅底 4.5:1，过 WCAG 小字线） |
| 输入框 | 高 36px，`bg-card` 或 `bg-surface-container-low`，聚焦 `ring-1 ring-primary/40` |
| chip / 状态 | `rounded-full`，底色 `bg-surface-container` 或 `bg-secondary-fixed` + `text-on-secondary-fixed` |
| 圆角 | **2026-10 整体 +10px**：卡片 22 / 内嵌块 18 / chip full（按钮按 size：lg=22、sm=18）。token 见 `index.css` 末尾 `:root` 的 `--radius-*` |

**AI 输出面板的唯一写法**：`ai-inset`（左侧 3px 主墨竖条）+ `bg-surface-container-low` + 正文色。
（首页「AI 随行手记」、`components/AIThinking.tsx` 都是这个写法；不再用大面积浅桃。）

**进度条**：容器 `bg-surface-container`，指示条 `bg-primary`（主墨），高 6px（主卡）/ 4px（列表行）。

**可折叠块**（"默认收起的长内容"，如分数明细、空条目）：
- 触发器：`variant="ghost"` 或纯文字按钮，正文 14px，右侧一个 `ChevronDown`（展开时旋转 180°）；
- 折叠区：`CollapsibleContent` + `pt-3`，内部沿用 14px 正文与 8px 圆角浅底块；
- 纪律：**折叠不等于藏数据** —— 收起的内容必须在同一页一点就能看到（不许做成"另一个页面/另一个弹窗"），
  并且展开后字段/数字一个都不能少；空条目折叠时必须写清"点开会出现什么、有几项"。

## 五、每页版式骨架

```
PageShell(标题 26/700 · 路径 · 一句人话 · 右侧最多 1 个主 CTA)
  ├─ 主角区 Panel（最大的内边距、唯一的进度条）
  ├─ 内容网格（只在有真数据时开第二列；不为了齐整加工具卡）
  └─ 次要动作：页面底部一行 ghost 按钮
```

- 空态：`EmptyState`（画布色 + 虚线框），文案必须是**真话**（禁止把零值文案套到有数据的场景）。
- 加载态：`AIThinking`（浅底 + 主墨条 + 骨架）。
- 错误态：明确原因 + 重试按钮，不允许静默空白。
- 打印：保留所有 `data-print` 属性；`resume-*` 类名不得改名。

## 七、两个必须知道的工程事实（2026-10 实测）

### 7.1 裸路由页面拿不到外壳内边距
`/test/*` 与 `/interview/session` 是**裸路由**：`router/index.tsx` 里它们只挂在 `RequireAuth`
（`/interview/session` 是 `BlankLayout`）下，**不在 `AppLayout` 里** → DOM 上没有 `main`、
没有 `pt-shell`、也没有 `px-margin`。所以：

- 这些页面的**顶部留白与两侧内边距要自己补**（`pt-shell px-margin pb-margin`），
  否则桌面端 44px 窗口头会压住内容（实测 `/test/question` 的进度行曾贴在 y=0）。
- 一屏固定布局的高度**不能**只写 `h-[calc(100svh-var(--spacing-shell))]`：那会少算外壳留白，
  内容整体上移 44px、按钮跳位。正确写法是引用 token **并把外壳留白也算进去**：

  ```
  h-[calc(100svh-var(--spacing-shell)-var(--spacing-margin)-44px)]   /* 44px = 窗口头高度 */
  ```

  `/test/question` 用的就是这一版，改前后按钮 y 坐标逐像素一致（734/724）。

### 7.2 同时跑多个 Agent 时的两个坑
- **不要各自跑 `tsc -b`**：它写同一份增量构建缓存（`.tsbuildinfo`），并发会互相污染、
  报出不存在的类型错误。汇总时由一个人跑一次。
- Node 的绝对路径是
  `C:\Users\15972\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe`
  （中间是 `dependencies\node`，漏掉 `dependencies` 会 CommandNotFound）。

### 7.3 写高度类名时的三个实测坑（A1 用 `a1-css-probe.mjs` 逐条复现）
在 Tailwind 的**任意值**类名里写 `calc()` 时：

| 写法 | 实际结果 |
|---|---|
| `h-[calc(100svh-var(--spacing-shell))]` | ✅ 824px，正确（**单变量 calc 是唯一稳的写法**） |
| `h-[calc(100svh-var(--spacing-shell)-var(--spacing-margin)-44px)]` | ❌ 只减了第一段（=748），后两段被丢掉 |
| `h-[calc(100svh-var(--spacing-shell)-2rem-44px)]` | ❌ 整条类名没生成 |
| `h-svh` / `h-screen` / `h-[100svh]` | ❌ 整条类名没生成（computed height = 0） |

结论：**要减多项，就把它们合成一个 token**（这就是 `--spacing-shell-total` 的由来），
不要在类名里堆多个 `var()`/长度值。

### 7.4 两种会把整站弄白屏的注释写法（各踩到一次）
1. **`*/` 序列（含加粗写法 `**/xxx`）会提前闭合块注释** —— 后面的中文就变成代码被解析。
   这是 `router/index.tsx` 那次真正的根因（`**/test/question…`）：tsc 报 `TS1005/TS1127`，
   oxc 报 `Expected , or ] but found Identifier`。**注释里不要写 `**[...]`**，用「」代替。
2. **JSX 的 `{ }` 表达式里不要出现反引号**（注释里也不要）：oxc 会把它当模板字符串起点。

两条都属于"改一行注释、整站白屏"级别，改完任何文件都值得先跑：
```powershell
$node="C:\Users\15972\.dsh\dsh-runtimes\dsh-primary-runtime\dependencies\node\bin\node.exe"
& $node tools/render-check/check-syntax.mjs /src/router/index.tsx /src/pages/xxx/YourPage.tsx
# 全量：& $node tools/render-check/check-syntax-all.mjs   （108 个模块逐个问 dev server）
```

### 7.5 生产构建的深链白屏（既有缺陷，尚未修，需产品决策）
`frontend/vite.config.ts` 里 `base: './'` 是为 **Electron**（`file://` + `loadFile`）设的硬要求，
但 `npm run build`（Web 构建）也沿用了它 —— 于是 `dist/index.html` 里资源是相对路径：

```html
<script type="module" crossorigin src="./assets/index-xxxx.js"></script>
```

在 nginx + SPA fallback 下，浏览器打开 `/task/xxx` 会用 `/task/` 解析相对路径 →
请求 `/task/assets/index-xxxx.js` → 被 fallback 成 `index.html`（`content-type: text/html`）
→ 模块解析失败 → **整页白屏、连一个请求都不发**。

实测证据（2026-10，`tools/render-check/diag-build.mjs`）：
```
$ node tools/render-check/diag-build.mjs /task/d4e5...
=== 请求（浏览器实际发出的）=== (空)
=== console.error === Failed to load resource: 404 (×4)
=== 页面状态 === { "url": "/task/...", "rootChildren": 0, "textLen": 0 }
```
用 `vite build --base=/` 重构建同一份代码后，`regression.mjs`（RC_BASE_URL=4173）
**19/19 路由 + A/B/C/D + N1..N5 全 PASS、console error 0**。

⚠️ 为什么之前一直没被发现：`regression.mjs` 的判定只看"拿不拿到 URL / 有没有 pageerror"，
深链白屏时 URL 是对的、`pageerror` 也是 0（模块根本没执行），所以它报 PASS ——
**凡是"整页没执行"的故障，靠 pageerror 是抓不到的**，要看 `document.body.innerText` 长度。

建议修法（**已于 2026-10 实施**）：`vite.config.ts` 改成
`base: mode === 'electron' ? './' : '/'`（`build:electron` 已经传了 `--mode electron`）。
实测两端都正确：

| 构建 | 资源路径 | 说明 |
|---|---|---|
| `vite build`（Web） | `/assets/index-*.js` | 深链可用；`regression.mjs` on 4173 → **19/19 PASS、console error 0** |
| `vite build --mode electron` | `./assets/index-*.js` | `file://` 可用（配合 router 的 `createHashRouter`，按协议自动切换） |
