你的任务：给一份简历做 ATS（机器筛选）评分与逐条优化建议。

输入：
- 目标岗位：{target_job}
- 岗位关键词库（附录F）：{job_keywords}
- 学生希望重点优化的方向：{focus}
- 结构化简历内容（JSON）：{resume_json}

评分规则（总分 100）：
1. 关键词匹配 40 分：命中的岗位关键词数量 / 关键词总数，按比例折算。
2. 经历完整度 25 分：是否有实习/项目，是否有时间、角色、职责描述。
3. 成果量化 20 分：经历里出现数字、比例、规模的条目占比。
4. 结构规范 15 分：是否有明确的求职意向、教育背景、技能区，是否分段清晰。

输出规则：
1. ats_score 是上述四项之和（0-100，可有一位小数，不要全给 60 这种整数）。
2. completeness 是简历信息完整度（0-100），与 ats_score 不同：只看“信息写全了没有”。
3. matched_keywords / missing_keywords 必须是关键词库里的原词，不要自己造词。
4. suggestions 给 3-6 条，按**重要性从高到低**排序，每条必须：
   - 指明 section（basic/education/experience/project/skill/summary 之一）
   - 用 problem 说清现在哪里不行（引用原文片段更好）
   - 用 suggestion 给出可直接照做的动作
   - 尽量给 example（改写后的示例句，用学生自己的经历改写，不要编造新经历）
5. summary 是 3 句话内的整体点评，先肯定再指出最关键的一个问题。
6. 不要输出与目标岗位无关的通用废话（如“建议多参加实践”）。

输出要求：
- 只输出一个 JSON 对象，不要解释、不要 Markdown 代码块。
- JSON 结构：
{
  "ats_score": 62.5,
  "completeness": 70,
  "matched_keywords": ["需求分析"],
  "missing_keywords": ["PRD", "用户调研"],
  "suggestions": [
    {"section": "project", "problem": "项目描述只有一句“负责前端开发”", "suggestion": "补上项目目标、你的具体职责、最终结果", "example": "负责 3 个核心页面的开发，页面首屏加载从 2.1s 降到 0.8s"}
  ],
  "summary": "整体框架齐全，项目经历是最薄弱的一环。"
}
