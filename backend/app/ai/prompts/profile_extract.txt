你的任务：从下面这段学生自己写过的话里，抽取可用于更新职业画像的标签。

⚠️ **输入里只有学生自己写的字**（服务端保证）。如果哪一段看起来像 AI 说的话、
像提问、像安慰或点评，说明你读错了输入 —— 任何情况下都**不许**把它当成学生的原话。

可用的维度（只能从里面选）：
- 兴趣：技术、产品、设计、运营、数据、教育、金融、传媒、体制内……
- 能力：表达、逻辑、执行、学习、协作、抗压、复盘……
- 技能：Python、Java、前端、SQL、PPT、Excel、剪辑、写作……
- 痛点：缺项目、缺实习、表达差、迷茫、拖延、信息差……
- 焦虑：高、中、低
- 认知：清晰、模糊、偏差

抽取规则：
1. 只抽学生**真的写过**依据的标签，不要脑补，不要给每个人都贴“迷茫”。
2. 每条标签必须给出 evidence，而且 evidence 必须是**学生原话的连续片段**（20 字以内）：
   从输入里**原样复制一个连续子串**，**一个字都不许改** —— 不许换词、不许补主语、
   不许改标点、不许改错别字、不许把口语改写成通顺的句子、不许拼接两句、
   不许动任何字符（归一化后的大小写/空格差异不算，别的都算）。
   - ⚠️ **交付前逐字核对一遍**：把 evidence 原样粘回上面的输入里搜一次，
     **必须能一字不差地搜到**。搜不到就说明你改写了 —— 那就改回原样。
   - 真实事故（这条规则就是为了修它）：学生打的是"**我想学ai**"，被存成了
     "**我想学习ai**"（多一个"习"字）。一字之差，这段证据就永远无法在用户消息里
     原样找到，等于**凭空造了一句他没说过的话**（服务端会把这类证据整条丢掉，
     标签也因此失去原话）。
   - **找不到可原样复制的连续片段**（例如这条标签是你从好几句话里推出来的）时：
     把 evidence 写成**空字符串** `"evidence": ""`，只输出标签本身。
     **绝对不许自己概括、润色、拼一句像原话的句子** —— 宁可没有证据，也不许自己造。
     （"学生原话"与"AI 的话/你的转述"分不清时，同样留空；也不要在 evidence 里加
     "学生：""AI："这类前缀，加了前缀就说明这句话不是他说的。）
   - ⚠️ 没有"学生原话"就别输出带引号的伪原话；这一条比"多抽一条标签"重要得多。
   - ⚠️ 另一类真实事故（同样是这条规则要拦的）：曾经输入里混进了 AI 的回复，于是抽出了
     能力/学习 <- `会Java和C，说明你编程底子不算白纸`（AI 说的话）、
     痛点/缺项目 <- `有没有做过完整的小项目？`（AI 问的问题）、
     焦虑/中 <- `比空焦虑强多了`（AI 的安慰话）。这些"证据"后来被回述成"你上次说……"，
     用户看到的是**把 AI 的话安到自己头上**，属于最严重的杜撰（用户明令禁止）。
     所以：**只有输入里"学生"那一行里的字才算原话**，剩下的一律留空、不许抽成证据。
3. weight 表示可信度，0-1 之间：
   - 学生明确、反复表达 -> 0.8-1.0
   - 学生提过一次、语气模糊 -> 0.3-0.6
   - 只是AI猜测 -> 不要输出这条
4. 每条标签只输出一次，同一维度同一含义合并。
5. pain_points 是痛点标签的精简列表（最多3条），供后续生成成长任务使用。
6. summary 用一句话（30字以内）概括这位学生当前的状态。
7. 如果这段对话确实没有可用的新信息，返回空的 tags 数组，不要硬凑。

输出要求：
- 只输出一个 JSON 对象，不要任何解释、不要 Markdown 代码块。
- JSON 结构：
{
  "tags": [
    {"dimension": "兴趣", "label": "产品", "weight": 0.8, "evidence": "我想做跟用户打交道的事"}
  ],
  "pain_points": ["缺项目"],
  "summary": "对产品有兴趣但缺少实践经历"
}

对话内容（按时间顺序，只有学生自己写的话）：
{history}

学生最近一条发言：
{last_user_message}
