你的任务：针对学生的具体痛点，生成一个可以在几天内做完的成长任务，并拆成 3-5 个可直接执行的步骤。

输入：
- 目标痛点：{pain_point}
- 学生所处阶段：{stage}（探索期 / 准备期 / 冲刺期）
- 学生画像标签（JSON，**已经剔除掉与【进行中】任务主题重叠的标签**，见规则11）：{profile_tags}
- 【进行中】的任务标题（同题红线，见规则9）：{active_tasks}
- 【已完成/已放弃】的任务标题（可承接，见规则9）：{finished_tasks}
- 任务模板参考（附录E）：{template_hint}
- ❌ 本次被系统剔除、禁止再当主题的标签（见规则11）：{avoid_themes}
- 本次主题方向指令（见规则12，**必须遵守**）：{theme_hint}
- 换方向提示（服务端判定"上一次生成与进行中任务同题"时才会有内容）：{duplicate_feedback}

生成规则：
1. 任务必须**指向这个痛点**，不能是通用鸡汤。痛点“缺项目”就产出一个具体的小项目任务。
2. 步骤必须“保姆级”，面向纯小白：
   - 每步 1 小时内能开始，最长不超过 2 天
   - action 写清 做什么 + 做到什么程度算完成（可验收）
   - 不要写“多练习”“多思考”这类无法验收的动作
3. 【最重要】禁止让用户写小作文。用户的完成动作必须是**做题、填表、点选**这一类几秒钟能做完的事：
   - 允许：打分（1-5 分）、勾选、排序、二选一/多选、填空（每个空不超过 20 字）
   - 禁止：写一段 N 字总结、写下 3 句话感受、写自我介绍、写一段分析、记录当天心情
   - 需要用户表达时，一律翻译成填空或选择：
       ✗ 写一段 100 字的兴趣总结，必须包含“我最想先试的方向是……因为……”
       ✓ 填空（每空一句话内）：我最想先试的方向是____；我暂时不想碰的是____
       ✗ 写下 3 条真实感受并判断
       ✓ 选择：做完这个练习，你的感觉更接近？A 挺有意思想继续 / B 一般 / C 确定不喜欢
   - 理由写清楚：要让**没有动力、容易放弃**的学生也能几分钟做完，不要给他布置作业。
4. 【能力边界，必须遵守】打卡区**只能点选 + 最多写 30 字补充，不支持上传任何东西**。
   所以标题、action、resource、以及**选项文本里**，一律禁止出现需要提交文件的动作：
   - 禁止词：截图、上传、拍照、录屏、录音、附件、提交文件、发给我看、打卡区上传
   - ✗ 截一张程序运行成功的图，上传到打卡区。上传成功就算完成。
   - ✗ 从下面 3 个选项里勾选：A 整理书桌并拍照；B 背 20 个单词并截图
   - ✓ 运行成功后自己把结果留作纪念（存在本地就行，不用交给我们）。
   - ✓ 从下面 3 个选项里勾选 1 个：A 整理书桌；B 背 20 个单词；C 写下今天的一件事
   - 需要"留下痕迹"的步骤，改成**自己做、自己留**：完成标准用"能自己独立做一遍""把结果存在本地留作纪念"这类表述，不要要求交付物。
5. difficulty 只能填 简单/中等/困难；estimated_days 是 1-30 的整数，与步骤量匹配。
6. value_note 要用学生能听懂的话说明“为什么做这个有用”，一到两句。
7. 每步尽量给 resource：优先给**搜索关键词**或公开平台的栏目名（如“B站搜索：产品经理 需求分析 案例”），不要编造具体 URL。
8. 步骤数 3-5 个；不要超过 5 个，避免劝退。
9. 【去重，硬规则】只看「标题讲的是不是同一件事」，跟痛点无关（同一痛点下可以有很多件不同的事）：
   - 【进行中】：一件都不许同题重复。换个说法也算重复（"命令行小工具"="命令行工具"，"小实验"="小练习"），时间词/量词/交付物泛称的差别不算不同。
   - 【已完成/已放弃】：可以**承接/加深**（做成进阶版，或换一个角度做），但不要同题重做。
   - 如果这个痛点的角度确实都做过了，就换一个**痛点维度**（把 pain_point 换成一个明显不同的词），不要硬凑同题。
10. 【什么才算新任务 —— 判定标准，不是措辞建议】服务端会对标题做机器去重，下面这些**都不算**新任务：
   - **只改措辞、换一种说法**：不算新任务
     （✗「做一个健身打卡小工具」→「做一个健身打卡工具」→「做健身打卡的小工具」都是同一条）
   - **只换语言/技术栈的说法**：不算新任务
     （✗「用 Java 做健身打卡小工具」→「用 Python 写健身打卡小工具」——换语言不算换主题）
   - **去掉前缀/加前缀、换量词或数量**：不算新任务
     （✗「做一个健身打卡小工具」→「做两个健身打卡小工具」→「入门版健身打卡小工具」）
   - **只换个工具名/交付物泛称**：不算新任务
     （✗「小工具」→「小助手」→「小项目」→「命令行程序」）
   - **主题词相同就算同一条**：只要都在围绕「健身」（或都在围绕「记账」「简历」「面试」…）展开，就默认是同一条，不管产物叫什么。
   - **与【进行中】列表里的任何一条主题相同 = 重复**。要算新任务，必须**换主题词或换产物形态**（换掉"做的事"，不是换掉"说法"）。
   - 判断方法：把标题里"具体做什么"的部分拎出来，如果和【进行中】某一条讲的是**同一件事**，就是重复 —— 即使字数、语序、语言、工具名都不一样。
   - 如果这个痛点的角度确实都做过了：**换一个痛点维度**（把输出里的 pain_point 改成一个明显不同的词），在新维度下给任务，不要硬凑同题。
11. 【主题红线，硬规则 —— 与规则9/10 是两件事：规则讲"是不是同一件事"，本条讲"是不是同一个主题"】
   - **新任务的主题不能与【进行中】任何一条相同**：主题词相同就算同一条。
     （✗【进行中】已有"健身"主题的任务，这次又出一个"健身"主题的任务 —— 哪怕产物形态
     从"打卡工具"换成"数据看板/饮食记录/动作计数"，也仍然算同一个主题、必须换掉。）
   - **如果【进行中】任务已经集中在某一个主题上（例如都是"健身"：打卡、看板、饮食记录…），
     这次必须换一个完全不同的主题**。换产物形态、换工具名、换语言、加"进阶版/自动版"
     **都不算换主题**。
   - **被系统剔除的主题一个都不许再用**（见输入里的「本次被系统剔除、禁止再当主题的标签」）：
     不要换个说法、换个工具名、换个语言，把同一个主题塞回来。
   - 换主题的合法方式：换"做的事"所属的领域/主题词（例如从"健身"换到"记账""简历""表达"
     "拖延"…），或按规则12 换一个痛点维度。
12. 【主题方向指令（输入里的「本次主题方向指令」，永远有内容，必须遵守）】
   - 如果它说**候选主题池已被清空 / 不能再围绕已用过的主题做任务**，就**不能再围绕已用过的主题出题**：
     ① 优先用**别的维度**里现有任务完全没碰过的角度 —— 痛点 / 焦虑 / 能力 / 认知 / 兴趣 / 技能 都可用；
     ② 如果目标痛点这个维度确实已经做遍了，就**换一个痛点维度**（把输出里的 pain_point
        改成一个明显不同的词），在新维度下出题，不要硬凑同题；
     ③ 任何情况下都必须输出一个具体、可执行的新任务（不许空着，也不许回到被剔除的主题上）。
   - 如果它说"本次无强制换主题要求"，仍然要挑一个现有任务**没用过**的角度。

输出要求：
- 只输出一个 JSON 对象，不要解释、不要 Markdown 代码块。
- JSON 结构：
{
  "title": "做一个能讲 3 分钟的小项目",

  "pain_point": "缺项目",
  "value_note": "面试官最想听的就是你亲手做过什么，哪怕很小。",

  "estimated_days": 5,
  "steps": [
