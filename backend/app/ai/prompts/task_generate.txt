你的任务：针对学生的具体痛点，生成一个可以在几天内做完的成长任务，并拆成 3-5 个可直接执行的步骤。

输入：
- 目标痛点：{pain_point}
- 学生所处阶段：{stage}（探索期 / 准备期 / 冲刺期）
- 学生画像标签（JSON）：{profile_tags}
- 已完成过的任务标题（避免重复）：{existing_tasks}
- 任务模板参考（附录E）：{template_hint}

生成规则：
1. 任务必须**指向这个痛点**，不能是通用鸡汤。痛点“缺项目”就产出一个具体的小项目任务。
2. 步骤必须“保姆级”，面向纯小白：
   - 每步 1 小时内能开始，最长不超过 2 天
   - action 写清 做什么 + 做到什么程度算完成（可验收）
   - 不要写“多练习”“多思考”这类无法验收的动作
3. 【最重要】禁止让用户写小作文。用户的完成动作必须是**做题、填表、点选**这一类几秒钟能做完的事：
   - 允许：打分（1-5 分）、勾选、排序、二选一/多选、填空（每个空不超过 20 字）
   - 禁止：写一段 N 字总结、写下 3 句话感受、写自我介绍、写一段分析、记录当天心情
   - 需要用户表达时，一律翻译成填空或选择：
       ✗ 写一段 100 字的兴趣总结，必须包含“我最想先试的方向是……因为……”
       ✓ 填空（每空一句话内）：我最想先试的方向是____；我暂时不想碰的是____
       ✗ 写下 3 条真实感受并判断
       ✓ 选择：做完这个练习，你的感觉更接近？A 挺有意思想继续 / B 一般 / C 确定不喜欢
   - 理由写清楚：要让**没有动力、容易放弃**的学生也能几分钟做完，不要给他布置作业。
4. difficulty 只能填 简单/中等/困难；estimated_days 是 1-30 的整数，与步骤量匹配。
5. value_note 要用学生能听懂的话说明“为什么做这个有用”，一到两句。
6. 每步尽量给 resource：优先给**搜索关键词**或公开平台的栏目名（如“B站搜索：产品经理 需求分析 案例”），不要编造具体 URL。
7. 步骤数 3-5 个；不要超过 5 个，避免劝退。
8. 不要与 existing_tasks 里已有的任务重复。

输出要求：
- 只输出一个 JSON 对象，不要解释、不要 Markdown 代码块。
- JSON 结构：
{
  "title": "做一个能讲 3 分钟的小项目",
  "description": "选一个你感兴趣的小场景，做出一个能演示的最小版本。",
  "pain_point": "缺项目",
  "value_note": "面试官最想听的就是你亲手做过什么，哪怕很小。",
  "difficulty": "中等",
  "estimated_days": 5,
  "steps": [
    {"order": 1, "title": "选定场景并写一句话目标", "action": "填空一句话：我要给谁解决什么问题。写完就算完成。", "resource": "搜索关键词：最小可行产品 案例"},
    {"order": 2, "title": "看完 2 个入门视频后选一个方向", "action": "从 3 个候选方向里勾选 1 个你最想试的，就算完成。", "resource": "B站搜索：入门 实操 30分钟"}
  ]
}
