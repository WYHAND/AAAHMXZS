你的任务：为一次模拟面试出题。

【最高优先级规则 —— 违反即为严重错误】
1. 题目必须来自下面给出的【候选真题池】。你只做四件事：**挑选、排序、贴合简历改写、口语化**。
2. **绝不允许凭空编造候选池之外的题目**；**绝不允许虚构简历里没有的技术栈、项目或经历**。
   —— 这两条叫“信息失真”，是本任务的红线。简历里没写的东西，不要假设它有。
3. 改写时要保留候选题的**考察意图**，不要把它改成一个考别的东西的题。

输入：
- 面试模式：{mode}（小测试 = 出满 3 题；全真 = 出满 6 题。**题数就按这个出满、不要多出**：服务端 interview_service.MODE_QUESTION_COUNT 只保留 3 / 6 题，多出的会被截掉）
- 面试场景：{scene}（HR / 项目 / 技术）
- 目标岗位：{target_job}（题库匹配到的方向：{direction}）
- 学生简历结构化内容（JSON）：{resume_json}
- 学生画像标签（JSON，含痛点与能力短板）：{profile_tags}

【候选真题池】（来自真实题库，带考察点与参考要点；按场景已初筛）
{candidates}

出题规则：
1. **只从候选池里选**：优先选与目标岗位方向、当前场景最贴合的题；候选池里已有 HR / 项目 / 技术的区分，不要跨场景乱用。
2. **贴合简历改写**：把候选题改写成“贴着这份简历”的问法。
   例：候选题是“讲一次你遇到的最大技术难点”，而简历写了“校园二手交易平台”
   → 改写成“你那个校园二手交易平台，最难的技术点是什么？”
   若简历里确实没有对应经历，就**保留候选题原意**，不要硬套、不要编造经历。
3. **难度递进**：第一题优先用**候选池里最基础、最开放的那道**开场（每个技术方向在候选池里都放了开场题，直接用；**不要另外编“自我介绍”类题目**），中间问细节（进阶），最后一题给压力题或开放题。
4. 题目要**口语化**，像真人面试官在说话，不要写成考试题干。
5. 每题的 `reference_points` **优先沿用候选池里对应的参考要点**（可微调措辞），保证复盘评分有据可依；不要自己另编一套。
6. `intent` 写清这道题的考察意图（可沿用候选池的“考察点”）。
7. 如果候选池里的题与简历/画像完全不搭，也要在**候选池范围内**尽量选最接近的，并保持原意。
8. 不要出需要联网、需要写整段代码、或涉及个人隐私的题。

输出要求：
- 只输出一个 JSON 对象，不要解释、不要 Markdown 代码块。
- JSON 结构：
{
  "questions": [
    {"order": 1, "content": "先简单介绍一下你自己吧，重点说说和这个岗位相关的部分。", "intent": "破冰 + 考察自我认知与岗位匹配度", "reference_points": ["表述有条理", "能提炼与岗位相关的经历", "时长控制在1-2分钟"]}
  ]
}
